# Используемые возможности PostgreSQL

## Логическая репликация

В проекте используется логическая репликация между двумя экземплярами PostgreSQL

Внешняя база `directory_db` публикует таблицы:

- `office.departments`
- `office.roles`
- `office.employees`
- `office.employee_roles`

Основная база `office_booking_db` создает подписки на эти публикации

Репликация демонстрирует работу со связанными таблицами, где сотрудники зависят от отделов, а назначения ролей зависят от сотрудников и ролей

## Ограничения целостности

В модели используются:

- первичные ключи
- внешние ключи
- уникальные ограничения
- `CHECK`-ограничения
- каскадное удаление для связующих таблиц

## Диапазоны времени

Бронирования хранят период в поле `booked_period` типа `TSTZRANGE`

Это позволяет использовать оператор пересечения `&&` для проверки конфликтов по времени

## Запрет пересекающихся бронирований

В таблице `booking.bookings` используется `EXCLUDE USING gist`

Это ограничение запрещает два активных бронирования одного рабочего места на пересекающиеся интервалы

Для этого включено расширение:

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;
```

## Триггеры

В проекте есть триггеры для:

- обновления поля `updated_at`
- проверки бизнес-правил при создании бронирования
- записи истории изменения статусов
- аудита изменений

## Аудит

Функция `audit.log_row_change()` записывает изменения в `audit.change_log`

В аудит попадают изменения бронирований, рабочих мест, планов этажей и координат рабочих мест

## Представления

Представление `booking.active_bookings` собирает активные бронирования с данными сотрудника, офиса, этажа, зоны и рабочего места

## Индексы

Индексы добавлены для:

- поиска сотрудников по отделу
- поиска рабочих мест по зоне
- поиска бронирований по сотруднику
- проверки пересечений бронирований через GiST
- просмотра истории статусов
- выборки аудита

## Docker Compose

В `docker-compose.yml` настроены два PostgreSQL-контейнера

Для логической репликации включены параметры:

- `wal_level=logical`
- `max_replication_slots=10`
- `max_wal_senders=10`
- `max_logical_replication_workers=10`
- `max_worker_processes=16`
