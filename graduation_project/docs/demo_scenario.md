# Сценарий демонстрации проекта

## 1. Запуск окружения

Перейти в каталог проекта:

```bash
cd graduation_project
```

Запустить базы данных:

```bash
docker compose up -d
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

Ожидаемый результат: контейнеры `office_booking_db` и `directory_db` находятся в состоянии `healthy`

## 2. Настройка логической репликации

```bash
docker compose exec -T office_booking_db psql -U office_booking_user -d office_booking -v ON_ERROR_STOP=1 -f /scripts/01_setup_replication.sql
```

Что показать:

- создаются подписки на отделы, роли, сотрудников и назначения ролей
- реплицируются связанные таблицы
- порядок подписок учитывает внешние ключи

## 3. Имитация изменений во внешнем каталоге

```bash
docker compose exec -T directory_db psql -U directory_user -d directory_service -v ON_ERROR_STOP=1 -f /scripts/02_directory_changes.sql
```

Что показать:

- добавляется новый отдел `product`
- изменяется название отдела `hr`
- добавляется роль `floor_manager`
- добавляется новый сотрудник
- меняется должность сотрудника
- сотрудник деактивируется
- меняются назначения ролей

## 4. Демонстрация бронирований

```bash
docker compose exec -T office_booking_db psql -U office_booking_user -d office_booking -v ON_ERROR_STOP=1 -f /scripts/03_booking_demo.sql
```

Что показать:

- сотрудники, отделы и роли пришли из внешней базы
- в БД хранится SVG-план этажа
- рабочие места имеют координаты на плане
- успешное бронирование создается
- пересекающееся бронирование отклоняется
- бронирование недоступного рабочего места отклоняется
- изменение статуса попадает в историю
- изменения попадают в аудит

## 5. Отчеты

```bash
docker compose exec -T office_booking_db psql -U office_booking_user -d office_booking -v ON_ERROR_STOP=1 -f /scripts/04_reports.sql
```

Что показать:

- список сотрудников с отделами и ролями
- точки рабочих мест на плане этажа
- активные бронирования
- загрузка офиса по дням
- загрузка по зонам
- свободные рабочие места на выбранный период
- история статусов
- журнал аудита

## 6. Негативные кейсы

```bash
docker compose exec -T office_booking_db psql -U office_booking_user -d office_booking -v ON_ERROR_STOP=1 -f /scripts/05_negative_cases.sql
```

Что показать:

- нельзя создать сотрудника с несуществующим отделом
- неактивный сотрудник не может бронировать рабочее место
- нельзя создать бронирование с некорректным периодом
- нельзя сохранить некорректный SVG-план
- нельзя сохранить точку рабочего места с отрицательными координатами

## 7. ER-модель

Открыть файл:

```text
docs/er_model.svg
```

Что показать:

- слева внешний каталог
- по центру офисная модель
- справа модель бронирований
- снизу аудит
- пунктирные стрелки показывают логическую репликацию
