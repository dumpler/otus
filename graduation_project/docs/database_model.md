# Описание модели данных

## Схемы базы данных

В основной базе используются три схемы:

- `office` - офисная структура, сотрудники, роли, планы этажей и рабочие места
- `booking` - бронирования, статусы, причины отмены и история статусов
- `audit` - журнал изменений

Во внешней базе `directory_db` используется схема `office`, чтобы имена реплицируемых таблиц совпадали с основной БД

## Реплицируемые таблицы

Таблица `office.departments` хранит отделы компании

Она реплицируется из внешнего каталога и используется как справочник для сотрудников

Таблица `office.roles` хранит роли пользователей: обычный сотрудник, администратор офиса, аудитор, менеджер этажа

Таблица `office.employees` хранит сотрудников

Поле `department_code` связано с `office.departments(code)`

Таблица `office.employee_roles` реализует связь многие-ко-многим между сотрудниками и ролями

## Локальные таблицы офисной структуры

Таблица `office.offices` хранит офисы компании

Таблица `office.floors` хранит этажи офисов

Таблица `office.zones` хранит зоны этажа, например open space или quiet zone

Таблица `office.workplace_types` хранит типы рабочих мест

Таблица `office.workplaces` хранит рабочие места и их признаки: монитор, док-станция, активность

Таблица `office.floor_plans` хранит SVG-планы этажей в поле `svg_content`

Таблица `office.workplace_map_points` хранит координаты рабочих мест на SVG-плане

Таблица `office.workplace_unavailability` хранит периоды недоступности рабочих мест, например ремонт или замена оборудования

## Таблицы бронирования

Таблица `booking.booking_statuses` хранит статусы бронирования

Таблица `booking.cancellation_reasons` хранит причины отмены

Таблица `booking.bookings` хранит бронирования сотрудников

Основное поле времени - `booked_period` типа `TSTZRANGE`

Таблица `booking.booking_status_history` хранит историю изменения статусов бронирований

## Аудит

Таблица `audit.change_log` хранит изменения по важным таблицам

В журнал попадают операция, первичный ключ строки, старые и новые данные в формате `JSONB`
