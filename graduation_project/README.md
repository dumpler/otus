# Выпускной проект: система бронирования рабочих мест в офисе

## Идея проекта

Проект представляет собой информационную систему для управления гибридным офисом

Сотрудники бронируют рабочие места на выбранные даты и временные интервалы, а администраторы управляют офисами, этажами, зонами, SVG-планами этажей, точками рабочих мест на карте и правилами бронирования

Проект показывает возможности реляционной базы данных: проектирование схемы, ограничения целостности, транзакции, индексы, триггеры, аудит, отчетность и логическую репликацию связанных таблиц из внешней базы

## Бизнес-сценарий

Компания использует модель гибридного офиса

У сотрудников нет постоянно закрепленных рабочих мест, поэтому перед посещением офиса сотрудник заранее бронирует свободное место

Данные отделов, сотрудников, ролей и назначений ролей ведутся во внешней системе, похожей на AD/LDAP

Система бронирования получает эти связанные справочники через логическую репликацию, а операционные данные по офисам, планам этажей и бронированиям хранит локально

## Основные возможности

- ведение справочника офисов, этажей, зон и рабочих мест
- хранение SVG-планов этажей
- хранение координат рабочих мест на плане этажа
- ведение справочника сотрудников и отделов
- учет ролей сотрудников
- бронирование рабочих мест на дату и временной интервал
- запрет пересекающихся бронирований одного рабочего места
- управление статусами бронирований
- административное управление доступностью рабочих мест
- аудит важных изменений
- аналитические отчеты по загрузке офисов
- логическая репликация отделов, сотрудников, ролей и назначений ролей из отдельной базы данных

### Имитация внешнего каталога

В проекте используется отдельный экземпляр PostgreSQL, который имитирует внешнюю систему с отделами, сотрудниками и ролями

Эта база выступает источником логической репликации для связанных таблиц: `office.departments`, `office.roles`, `office.employees` и `office.employee_roles`

## Локальная инфраструктура

Локальное окружение содержит два контейнера PostgreSQL:

- `office_booking_db` - основная база данных проекта
- `directory_db` - имитация внешнего каталога отделов, сотрудников и ролей

Запустить базы данных:

```bash
docker compose up -d
```

Остановить базы данных:

```bash
docker compose down
```

Подключение к основной базе данных:

```text
Host: localhost
Port: 5432
Database: office_booking
User: office_booking_user
Password: office_booking_password
```

Подключение к базе данных внешнего каталога:

```text
Host: localhost
Port: 5433
Database: directory_service
User: directory_user
Password: directory_password
```

## Демонстрационные SQL-сценарии

Настроить логическую репликацию отделов, сотрудников, ролей и назначений ролей из внешнего каталога в основную базу:

```bash
docker compose exec -T office_booking_db psql -U office_booking_user -d office_booking -v ON_ERROR_STOP=1 -f /scripts/01_setup_replication.sql
```

Сымитировать изменения во внешнем каталоге:

```bash
docker compose exec -T directory_db psql -U directory_user -d directory_service -v ON_ERROR_STOP=1 -f /scripts/02_directory_changes.sql
```

Запустить демонстрационный сценарий бронирований, ограничений, триггеров, истории статусов и аудита:

```bash
docker compose exec -T office_booking_db psql -U office_booking_user -d office_booking -v ON_ERROR_STOP=1 -f /scripts/03_booking_demo.sql
```

Запустить отчетные запросы:

```bash
docker compose exec -T office_booking_db psql -U office_booking_user -d office_booking -v ON_ERROR_STOP=1 -f /scripts/04_reports.sql
```

Запустить негативные кейсы:

```bash
docker compose exec -T office_booking_db psql -U office_booking_user -d office_booking -v ON_ERROR_STOP=1 -f /scripts/05_negative_cases.sql
```
