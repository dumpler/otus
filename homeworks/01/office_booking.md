# База данных office_booking

## Назначение

`office_booking` - основная база данных системы бронирования рабочих мест в офисе

База хранит структуру офиса, сотрудников, роли, рабочие места, SVG-планы этажей, бронирования, историю изменения статусов и журнал аудита

Основной сценарий: сотрудник выбирает свободное рабочее место на нужный временной интервал, система проверяет доступность места и создает бронирование

## Схемы

В базе используются три схемы:

- `office` - офисная структура, сотрудники, роли, планы этажей и рабочие места
- `booking` - бронирования, статусы, причины отмены и история статусов
- `audit` - журнал изменений важных таблиц

## Схема office

### office.departments

Справочник отделов компании

Основные поля:

- `id` - первичный ключ
- `code` - уникальный код отдела
- `name` - название отдела
- `is_active` - признак активности
- `created_at`, `updated_at` - даты создания и обновления

Таблица используется сотрудниками через поле `office.employees.department_code`

### office.employees

Справочник сотрудников

Основные поля:

- `id` - первичный ключ сотрудника
- `email` - уникальный email
- `last_name` - фамилия
- `first_name` - имя
- `middle_name` - отчество
- `department_code` - ссылка на `office.departments(code)`
- `position_name` - должность сотрудника
- `is_active` - признак активности
- `source_updated_at` - время последнего обновления записи в источнике данных
- `replicated_at` - время попадания записи в основную базу

Сотрудник используется как владелец бронирования, автор создания бронирования и пользователь, отменивший бронирование

### office.roles

Справочник ролей пользователей

Основные поля:

- `id` - первичный ключ
- `code` - уникальный код роли
- `name` - название роли
- `description` - описание роли
- `is_active` - признак активности

Примеры ролей: обычный сотрудник, администратор офиса, аудитор

### office.employee_roles

Связующая таблица между сотрудниками и ролями

Основные поля:

- `employee_id` - ссылка на `office.employees(id)`
- `role_code` - ссылка на `office.roles(code)`
- `assigned_at` - дата назначения роли

Первичный ключ составной: `(employee_id, role_code)`

### office.offices

Справочник офисов компании

Основные поля:

- `id` - первичный ключ
- `code` - уникальный код офиса
- `name` - название офиса
- `address` - адрес офиса
- `timezone` - часовой пояс офиса
- `is_active` - признак активности

### office.floors

Справочник этажей офисов

Основные поля:

- `id` - первичный ключ
- `office_id` - ссылка на `office.offices(id)`
- `number` - номер этажа
- `name` - название этажа
- `is_active` - признак активности

Для одного офиса номер этажа уникален: `UNIQUE (office_id, number)`

### office.zones

Справочник зон этажа

Основные поля:

- `id` - первичный ключ
- `floor_id` - ссылка на `office.floors(id)`
- `code` - код зоны
- `name` - название зоны
- `description` - описание зоны
- `is_quiet_zone` - признак тихой зоны
- `is_active` - признак активности

Для одного этажа код зоны уникален: `UNIQUE (floor_id, code)`

### office.workplace_types

Справочник типов рабочих мест

Основные поля:

- `id` - первичный ключ
- `code` - уникальный код типа
- `name` - название типа

Примеры типов: обычное рабочее место, стоячий стол, фокус-комната

### office.workplaces

Справочник рабочих мест

Основные поля:

- `id` - первичный ключ
- `zone_id` - ссылка на `office.zones(id)`
- `type_id` - ссылка на `office.workplace_types(id)`
- `code` - код рабочего места
- `name` - название рабочего места
- `has_monitor` - наличие монитора
- `has_docking_station` - наличие док-станции
- `is_active` - признак активности

Для одной зоны код рабочего места уникален: `UNIQUE (zone_id, code)`

### office.floor_plans

Таблица SVG-планов этажей

Основные поля:

- `id` - первичный ключ
- `floor_id` - ссылка на `office.floors(id)`
- `version` - версия плана
- `file_name` - имя SVG-файла
- `svg_content` - содержимое SVG
- `width_px`, `height_px` - размеры плана в пикселях
- `is_active` - признак активности

Ограничения:

- `width_px > 0`.
- `height_px > 0`.
- `svg_content LIKE '%<svg%'`.
- версия плана уникальна в рамках этажа: `UNIQUE (floor_id, version)`

### office.workplace_map_points

Таблица координат рабочих мест на SVG-плане

Основные поля:

- `id` - первичный ключ
- `floor_plan_id` - ссылка на `office.floor_plans(id)`
- `workplace_id` - ссылка на `office.workplaces(id)`
- `x_px`, `y_px` - координаты точки на плане
- `width_px`, `height_px` - размеры области рабочего места
- `rotation_deg` - угол поворота
- `label` - подпись на плане

Ограничения:

- координаты не могут быть отрицательными
- ширина и высота должны быть больше нуля
- одно рабочее место может быть нанесено на один план только один раз

### office.workplace_unavailability

Таблица периодов недоступности рабочих мест

Основные поля:

- `id` - первичный ключ
- `workplace_id` - ссылка на `office.workplaces(id)`
- `unavailable_period` - период недоступности типа `TSTZRANGE`
- `reason` - причина недоступности
- `created_at` - дата создания записи

Ограничения:

- начало периода должно быть раньше окончания
- периоды недоступности одного рабочего места не должны пересекаться

## Схема booking

### booking.booking_statuses

Справочник статусов бронирования

Основные поля:

- `id` - первичный ключ
- `code` - уникальный код статуса
- `name` - название статуса
- `is_final` - признак финального статуса

Примеры статусов: создано, подтверждено, отменено, завершено

### booking.cancellation_reasons

Справочник причин отмены бронирования

Основные поля:

- `id` - первичный ключ
- `code` - уникальный код причины
- `name` - название причины
- `is_active` - признак активности

### booking.bookings

Основная таблица бронирований

Основные поля:

- `id` - первичный ключ
- `employee_id` - сотрудник, для которого создано бронирование
- `workplace_id` - забронированное рабочее место
- `status_id` - текущий статус бронирования
- `cancellation_reason_id` - причина отмены
- `booked_period` - период бронирования типа `TSTZRANGE`
- `comment` - комментарий
- `created_by_employee_id` - сотрудник, создавший бронирование
- `cancelled_by_employee_id` - сотрудник, отменивший бронирование
- `created_at`, `updated_at` - даты создания и обновления
- `cancelled_at` - дата отмены

Ограничения:

- начало бронирования должно быть раньше окончания
- причина отмены должна быть заполнена только вместе с датой отмены
- активные бронирования одного рабочего места не должны пересекаться по времени

Пересечения запрещаются ограничением `EXCLUDE USING gist` по полям `workplace_id` и `booked_period` для статусов `created` и `confirmed`

### booking.booking_status_history

Таблица истории изменения статусов бронирований

Основные поля:

- `id` - первичный ключ
- `booking_id` - ссылка на бронирование
- `old_status_id` - предыдущий статус
- `new_status_id` - новый статус
- `changed_by_employee_id` - сотрудник, изменивший статус
- `changed_at` - дата изменения

## Схема audit

### audit.change_log

Журнал изменений важных таблиц

Основные поля:

- `id` - первичный ключ
- `schema_name` - схема измененной таблицы
- `table_name` - имя измененной таблицы
- `operation` - операция `INSERT`, `UPDATE` или `DELETE`
- `row_pk` - первичный ключ измененной строки
- `old_data` - старые данные в формате `JSONB`
- `new_data` - новые данные в формате `JSONB`
- `changed_at` - дата изменения
- `changed_by` - пользователь базы данных, выполнивший изменение

## Ключевые ограничения целостности

- Уникальность кодов справочников: отделы, роли, офисы, типы рабочих мест, статусы и причины отмены
- Внешние ключи между офисами, этажами, зонами, рабочими местами и бронированиями
- Запрет пересекающихся бронирований одного рабочего места
- Запрет пересекающихся периодов недоступности одного рабочего места
- Проверка корректности временных интервалов
- Проверка корректности размеров SVG-плана и точек рабочих мест

## Основные сценарии использования

1. Администратор описывает офис: офис, этажи, зоны, рабочие места и SVG-план
2. На SVG-план наносятся координаты рабочих мест
3. Сотрудник выбирает рабочее место и временной интервал
4. Система проверяет активность сотрудника и рабочего места
5. Система проверяет, что рабочее место не закрыто на обслуживание
6. Система проверяет, что на это время нет другого активного бронирования
7. Создается запись в `booking.bookings`
8. При изменении статуса создается запись в `booking.booking_status_history`
9. Важные изменения попадают в `audit.change_log`
